## As recorded: Resetting the smoother on a DETECTED BOUNCE (bounce_reset)

**The mechanism version of the row below, and it FAILS the same gate.** Rather than counting rejections, the test is physical: in image pixels y grows downward, so a descending ball has vy > 0 and a bounce flips it — a rejection sitting ABOVE the prediction while the model still descends (with horizontal continuity, so an overhead false lock cannot trigger it) is a reflection, not an outlier, and resets on that frame. Same pre-registered gate (recall ≥−2, ghosts must not rise, `real_landing` ≥+5): **yt_match40 recall 52.7 → 53.8, ghosts 5 → 6, real_landing 70.9 → 74.5 (+3.6, short of +5)**; **yt_rally2 recall 42.2 → 41.5, ghosts 4 → 5, real_landing 80.0 → 80.0 (no headroom)**. **FAILS on both.** Directionally right where detections are sparse and inert where they are dense — **the third independent route to the same density dependence** (`max_gap_s`, `reset_after`, this). Kept as an off-by-default parameter with the numbers in the docstring so the measurement is not repeated; 4 tests pin that it is inert unless asked for. Ghost counts rest on 24/26 no-ball frames, inside sampling noise (trap 9) — the `real_landing` columns are load-bearing. **TWO FIXTURE BUGS worth remembering**: a synthetic "bounce" written as a parabola is exactly what a CA model predicts, so nothing is ever rejected and the flag looks inert; and even as a true velocity discontinuity, the model absorbs a **20 px/frame swing with zero rejections** — it takes 40 px to engage.

## As recorded: Bounce-aware smoother reset (bounce_reset), the MECHANISM version

**FAILS THE SAME GATE ON ALL THREE CALIBRATED CLIPS — and the third clip corrects the framing that motivated it.** The `reset_after` row below concluded a real fix must reset on a *detected bounce* rather than after N rejections. Built: the discriminator is physical, not a counter — in image pixels y grows downward, so a descending ball has `vy > 0` and a bounce flips it; a rejection sitting ABOVE the prediction while the model still descends (horizontal continuity required, so an overhead false lock cannot trigger it) resets on that frame. Same pre-registered gate (recall ≥−2, ghosts must not rise, real_landing ≥+5): **yt_match40 +3.6** real_landing (recall +1.1, ghosts +1), **yt_rally2 +0.0** (ghosts +1), **am_hard_utr +0.8** (recall +0.0, ghosts **−1**). Best case is 1.4 pts short of the bar. **Not shipped**; kept off-by-default with the numbers in the docstring. **THE CORRECTION:** the post-bounce loss was framed as one root cause with two payoffs, but on `am_hard_utr` — the 1.74 m amateur mount this project targets — `real_landing` is **already 74.2%** while speed is untrusted for **64 of 120** shots, and the printed reasons are dominated by *coverage* (`seen 10–49%<50%`) with "landing not tracked past bounce" in only ~20 of 64. On yt_match40 the landing cause dominates; on the target footage **the binding constraint is overall in-rally coverage, not the frames after the bounce.** Two attempts (threshold, then mechanism) failed to convert the diagnosis into a product gain, and the third clip says why it would not have paid much anyway.
